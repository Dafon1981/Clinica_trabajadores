# Cambios realizados

## Inventario y Excel

La aplicación ahora exige que el archivo tenga una pestaña llamada `INVENTARIO`. Solo lee código, descripción, unidad y stock de esa pestaña; no importa `REGISTRO 2026`, `TABLA`, `CONSUMO CEBADO`, `PRECIOS COSTOS` ni otras hojas. En productos existentes, la cantidad de la pestaña INVENTARIO sincroniza `stock_actual` sin crear un movimiento ficticio en Kardex.

## Kardex

La consulta operativa excluye los registros históricos `INICIAL`. Solo muestra `INGRESO`, `EGRESO`, `DEVOLUCION`, `AJUSTE_POSITIVO` y `AJUSTE_NEGATIVO`. Se añadió una columna de motivo y botones para copiar cada columna individualmente, además de `Copiar todo` para pegar el registro completo en Excel.

## Conciliación A0097

El producto `A0097 PAPEL TOALLA GOFRADO` quedó con stock actual `99`. Se corrigió el saldo duplicado de la carga inicial y se registró el egreso real de `1` paquete.

## APK

El repositorio original es una aplicación web estática de GitHub Pages y no contiene código Android/Expo. Por tanto, estos cambios no generan un APK nuevo. En teléfono se puede usar como web adaptable y añadir a la pantalla de inicio. Un APK independiente requeriría un proyecto móvil adicional.

## Seguridad RLS aplicada

Las nueve tablas de logística tienen RLS habilitado y una política `*_solo_rpc` para `anon` y `authenticated`, con `USING (false)` y `WITH CHECK (false)`. Esto bloquea el acceso directo a las tablas, mientras que las funciones RPC `SECURITY DEFINER` propiedad de `postgres` siguen funcionando. La prueba desde el navegador devolvió 0 filas en el acceso directo a `log_productos` y 37 personas mediante `log_listar_personal_login`. No se activó `FORCE ROW LEVEL SECURITY` para no bloquear las RPC existentes.

El asesor de Supabase todavía puede mostrar otros avisos de seguridad del proyecto general. La política aplicada se conserva en `supabase_rls_logistica_20260819.sql`. Referencia oficial: https://supabase.com/docs/guides/database/postgres/row-level-security.
